# Releases & Versioning

KoAkademy has **two release channels**: rolling `dev` pre-releases (automatic, on push) and **official stable releases** (tag push or manual dispatch). There is no beta channel. All channels build the same Docker image (`docker/Dockerfile`, `linux/amd64`) and publish to **GHCR** (`ghcr.io/yukazakiri/koakademy`); Docker Hub mirroring is optional.

## Dev pre-releases (automatic)

`auto-release.yml` runs on pushes to `develop`, `main`, or `master` (skipped on forks and for its own bot commits).

1. **Change filter** — pushes touching only docs, Markdown, workflows, or lint configs are skipped entirely.
2. **Version analysis** — the head commit's first line is matched against conventional-commit prefixes:

   | Prefix | Release type | Bump |
   | ------ | ------------ | ---- |
   | `feat` / `feature` | feature | dev-minor (patch resets) |
   | `fix` / `bugfix` | bugfix | dev-patch |
   | `break` / `major` / `breaking` | major | dev-minor (patch resets) |
   | `chore` / `docs` / `style` / `refactor` / `test` | chore | dev-patch |
   | anything else | patch | dev-patch |

   The base is the latest stable tag (`vX.Y.Z`, fallback `1.0.0`); the new tag is `v{BASE}-dev.{MINOR}.{PATCH}` (e.g. `v1.10.0-dev.14.3`), cross-checked against `version.json` and existing tags to avoid collisions.
3. **Build & push** — image tags: the dev tag, `dev-latest`, `{release_type}-{sha}`, and the branch name. OCI labels include title and `AGPL-3.0-or-later` license.
4. **Pre-release** — a GitHub **pre-release** with generated notes and `version.json` attached.
5. **Version commit** — `version.json` is committed back as `chore: update version to X [skip ci]` (with stale-write guards and rebase-retry).
6. **Notify** — optional Discord embed via `secrets.DISCORD_WEBHOOK_URL`.

## Official releases

Two ways to cut a stable release — both validate strict semver (`X.Y.Z`, optional leading `v`):

- **Push a tag** matching `v*.*.*` → `official-release-on-tag.yml` builds, tags the image with the release tag + `latest` + `stable-{sha}`, and creates a full GitHub release whose notes group merged PRs by label (Breaking / Features / Fixes / Refactors / Docs / Chores). It does **not** commit `version.json` back.
- **Actions → "Manual Official Release"** (`workflow_dispatch`) — inputs: `version`, `publish_latest`, `draft`, `prerelease`, `update_version_file`, `extra_notes`, `fail_if_tag_exists`. Must run from the default branch; can commit `version.json` back and notify Discord.

Before announcing public self-hosting, confirm that the linked GHCR package is also public; repository visibility does not substitute for package visibility. From a logged-out shell, both the stable image and the raw installer must resolve:

```sh
docker manifest inspect ghcr.io/yukazakiri/koakademy:<stable-tag>
curl --fail --silent --show-error --output /dev/null \
  https://raw.githubusercontent.com/yukazakiri/koakademy/master/scripts/install.sh
```

For release notes to categorize well, keep PR labels accurate — the [auto-labeler](./automation/) does the first pass.

## The `version.json` contract

Machine-written, embedded into images, attached to releases, and read back by the auto-release analysis. Shape:

```json
{
    "version": "1.10.0-dev.14.3",
    "image": "ghcr.io/yukazakiri/koakademy:v1.10.0-dev.14.3",
    "commit": "<sha>",
    "branch": "master",
    "timestamp": "2026-07-21T06:24:30Z",
    "build_url": "https://github.com/yukazakiri/koakademy/actions/runs/…",
    "release_type": "chore",
    "changelog": { "current": "…", "previous": "1.10.0-dev.14.2" },
    "metadata": { "author": "…", "workflow": "…", "repository": "yukazakiri/koakademy" }
}
```

Do not hand-edit `version.json`; the workflows own it.

## Optional publishing knobs

| Repository variable / secret | Effect |
| ---------------------------- | ------ |
| `PUBLISH_DOCKERHUB=true` + `DOCKERHUB_IMAGE` | Mirror image pushes to Docker Hub (auto-release and manual release only) |
| `DISCORD_WEBHOOK_URL` | Release notifications to Discord |
| `DOCKERHUB_USERNAME` / `DOCKERHUB_TOKEN` | Docker Hub credentials |

## Known quirks (read before changing these workflows)

- **`APP_URL` build-arg divergence:** `auto-release.yml` and `docker-latest.yml` bake `https://koacademy.yukazaki.com`; the two official-release workflows bake `https://koakademy.yukazaki.com` (note the missing `k`). Align deliberately if you touch them.
- **Naming drift:** release titles say "KoAcademy" and the Discord bot is "Koamishin Release Bot", while OCI labels and Composer metadata say "KoAkademy".
- The auto-release comment claims it "runs on develop only", but triggers include `main`/`master`, and `is_main` is hard-coded `false`.
- Dev tags anchor to the latest **stable** tag, so dev numbers can exceed the base (e.g. `1.10.0-dev.14.3` derives from stable `v1.10.0`).
- `docker-latest.yml` (manual dispatch) pushes only `ghcr.io/…:latest` — no tag, no release, no `version.json` write.
